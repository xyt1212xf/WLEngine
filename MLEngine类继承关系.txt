一、完整继承树
--------------------------------------------------------------------------------

【CRefcount 系】(引用计数根)
CRefcount
├── CObject                      (对象基类: Name; UE UObject 对标)
│   ├── CActor                   (演员: RootComponent + Components + Tick/BeginPlay)
│   │   │                          SetActorLocation 已改为驱动 RootComponent (UE 同款)
│   │   └── CCharacter           (角色空壳; UE ACharacter)
│   ├── CStaticMeshDescription   (LOD 源数据: 持 FMeshDescription; UE FStaticMeshSourceModel)
│   └── CStreamableRenderAsset   (空壳; UE UStreamableRenderAsset)
├── CResource                    (资源基类: UUID/状态/类型; ResourceType 枚举)
│   ├── CWorld                   (世界: 异步加载状态机 + Tick + 流送关卡管理; UE UWorld*)
│   └── CMesh                    (网格资源基类: 一对 VB/IB 指针)
│       └── CStaticMesh          (静态网格: SourceModels/RenderData/MaterialSlots; UE UStaticMesh)
├── CLevel                       (关卡: Actors 数组; UE ULevel)
├── CLevelStreaming              (流送关卡: 状态机 Unloaded/Loading/Loaded/Unloading; UE ULevelStreaming)
├── CGameMode                    (空壳; UE AGameModeBase)
├── CWorldPartition              (空壳; UE UWorldPartition)
├── CWorldSet                    (空壳)
└── CDX12RHIBuffer               (DX12 缓冲: ID3D12Resource + UploadBuffer + VB/IB/CBV 视图)
    └── CRHIBuffer               (⚠ 仍见"问题1": 继承方向反了)

【CComponent 系】(本次重构核心，已完全对齐 UE 的五层链)
CNonCopyable                    (删除拷贝/赋值的空基类)
└── CComponent                  (组件基类: tick + 名字)
    └── CActorComponent         (Actor 组件层; UE UActorComponent)
        └── CSceneComponent     (★Transform 归宿: Location/Rotation/Scale + GetWorldMatrix;
        │                        UE USceneComponent)
        └── CPrimitiveComponent (可见性 bVisible; UE UPrimitiveComponent)
            └── CMeshComponent  (网格组件层; UE UMeshComponent)
                └── CStaticMeshComponent (StaticMesh 引用 + GetMeshBatch;
                                          UE UStaticMeshComponent)


【CPlug 系】(插件 + 单例)
CPlug : TSingle<CPlug>           (引擎插件接口: Initialise/Process/Start)
└── CGraphicPlug                 (图形插件: 持 Device + Renderer; 启动渲染线程; 全接口 final)

【CEngine】
CEngine : TSingle<CEngine>       (引擎单例: World/Plugs/Platform/ThreadPool/资源加载)

【CDeviceBase 系】
CDeviceBase                      (设备抽象空壳)
└── CDX12RHIDevice               (DX12 设备: SwapChain/CommandQueue/RTV/Fence/BeginDraw/EndDraw)

【顶点工厂系】
CVertexStreamFactory             (抽象: BuildInputLayout 纯虚; UE FVertexFactory 简化)
└── CStaticVertexFactory         (静态网格顶点布局: SMeshVertexSchema; UE FLocalVertexFactory)

【工厂/管理器】(无继承或独立)
CRenderer                        (渲染器: 渲染线程 _Draw/_Begin/_Flush/_End 循环)

CResourceMgr / CResourceFactory  (资源管理/工厂)

【反射系】
StructInfo                       (类名/父类指针/继承缓存)
└── CClass                       (IsChildOfWalk/IsChildOfArray 查询)

二、POD 数据结构（无继承）
--------------------------------------------------------------------------------
--- 网格拓扑层 (MeshDescription.h 族) ---
FMeshVertex            (拓扑顶点: Position)
FMeshVertexInstance    (角点属性: VertexID + Normal/Tangent/UV0/Color)
FMeshTriangle          (三角形: VertexInstanceID[3] + PolygonGroupID)
FMeshPolygonGroup      (材质槽分组: Name + MaterialIndex)
FMeshDescription       (拓扑容器: 上述 4 数组 + Empty/IsEmpty/Validate + Num* 查询)

--- 烘焙层 (MeshAttributes.h) ---
FStaticMeshSection     (可绘制分段: MaterialIndex/FirstIndex/NumTriangles)
CMeshAttributes        (平铺流: Positions/Normals/Tangents/UVs/Colors + Indices + Sections
                        + BakeFromDescription 烘焙算法)
└─(继承) CStaticMeshAttributes (空壳子类; UE FStaticMeshAttributes 对标)

--- 渲染层 ---
FMeshBatch             (绘制批次: Mesh/LOD/VertexFactory/WorldMatrix/Section/Element; UE FMeshBatch)
FMeshBatchElement      (FirstIndex/NumIndices/BaseVertex/InstanceCount; UE FMeshBatchElement)
FViewMatrices          (View/Proj/ViewProj + ViewOrigin; UE FViewMatrices)
SDataStreamUnit        (单条顶点流: Buffer/Slot/Offset/Stride/Format)
SMeshVertexSchema      (8 条流 Position/Normal/Tangent/UV0-3/Color 的布局描述)
SInputElement          (输入布局元素)

--- 其他 ---
FObjectHeader          (对象头: Handle/Size/Name/GC标记)
SEvent                 (窗口消息事件)

四、三条主要数据流
--------------------------------------------------------------------------------

◆ 流程 A: 静态网格数据管线 (CPU 侧已通, GPU 上传仍断)
  CreateCube() 填拓扑
    → FMeshDescription (Vertex/VertexInstance/Triangle/PolygonGroup)
    → CMeshAttributes::BakeFromDescription()   平铺 + 按材质分组
    → CStaticMeshLODResources::InitResources() 拷贝 Sections/算包围球
    → [缺口] VB/IB 真实 GPU 上传 (CDX12RHIBuffer::Create 已具备能力, 未接线)
    → [缺口] VertexFactory 仍为 null

◆ 流程 B: 世界加载管线 (状态机已通, 硬编码 Cube)
  CEngine::LoadScene → CWorld::LoadAsync (线程池 threadDetach)
    → ParseFile()      (硬编码 Cube: CStaticMesh + CActor + CStaticMeshComponent,
                        SetVisible(true) + SetLocation(0,0,3))
    → BuildActors()    (装进 PersistentLevel)
    → 主线程 TickLoad: UploadGPUResources() [空] + InitActorsForPlay() → Ready
    → CWorld::Tick: 主关卡 Actor::Tick + 组件 tick; 流送关卡 Actor::Tick

◆ 流程 C: 渲染帧循环 (骨架就绪, 中间仍断)
  渲染线程 CRenderer::_Draw 循环:
    _Begin  → CDX12RHIDevice::BeginDraw
    _Flush  → [空]  ← 计划: CWorld::CollectVisibleMeshes(FViewMatrices, OutBatches)
                        (函数已声明, 实现为空)
                        遍历 Level→Actor→CStaticMeshComponent::GetMeshBatch
                        然后按 FMeshBatch 绑定 VB/IB/PSO → DrawIndexed
    _End    → CDX12RHIDevice::EndDraw

  注: CStaticMeshComponent::GetMeshBatch 已实现——取 LOD0/Section0,
      WorldMatrix 来自基类 CSceneComponent::GetWorldMatrix() (重构后走基类 ✔);
      但 InViewProj 参数被忽略, 且 bVisible=false 时直接返回。

六、当前设计问题（按严重度排序）
--------------------------------------------------------------------------------
【已解决·原问题2】Transform 已上移到 CSceneComponent，子类残留字段已删除，
                   组件析构泄漏也已修复。

【已解决·原问题3】CActor 构造时即 AddComponent<CSceneComponent>() 作为 RootComponent
                   (等价 UE 构造函数里 CreateDefaultSubobject<USceneComponent> + SetRootComponent)。
                   AddComponent 通用模板用 if constexpr + is_convertible_v 自动识别
                   SceneComponent 子类。SetActorLocation/GetActorLocation 不再空指针。
                   ⚠ 残留语义缺口: 尚无 AttachToComponent 机制 —— Root 是个普通
                   CSceneComponent, 后加的 CStaticMeshComponent Transform 独立于 Root,
                   SetActorLocation 移动 Root 时网格组件不会跟随。
                   过渡方案: 补 SetRootComponent(CSceneComponent*) 允许后期换根;
                   正式方案: P2 做 AttachToComponent/相对 Transform 层级(UE 同款)。

【已解决·原P1-B】CStaticMeshLODResources::InitResources 已接通 CRHIBuffer::Create,
                   Position/Tangent/Color/Index 四个 buffer 真实上传 GPU 完成
                   (默认堆 + 上传堆拷贝 + 屏障 + ExecuteUploadAndWait 全流程)。

【问题1】CRHIBuffer 继承方向反了 (结构性, ★用户已决定不改, 仅存档)
  现状: CRHIBuffer : CDX12RHIBuffer  (抽象层继承实现层)
  UE 的做法: FRHIBuffer 是纯虚基类, FD3D12Buffer : FRHIBuffer 是实现。
  结论: mini 引擎只做 DX12, 保持现状可接受。

【架构决策·图形API层统一约定 (2026-10-11 定)】
  所有图形API相关类统一采用 "C抽象类 : CDX12具体类" 方向:
    CShader : CDX12Shader : CResource, CRHIBuffer : CDX12RHIBuffer
  将来换 API 用宏在编译期切换基类 (如切到 COpenGLShader)。
  (UE 是"抽象基类 + 实现子类", 方向相反; 用户明确选择不改)
  配套纪律(保证宏切换可行):
    1. 具体 API 类(CDX12*)不暴露给上层 —— DX12 专属类型/头文件
       (ID3DBlob/D3D12_*/d3d12.h) 只允许出现在 DX12*.h/.cpp 中
    2. GlobalShader/Renderer/SolidColorShader 等上层文件禁止出现任何 ID3D*/D3D12_* 类型
    3. DX12 类的创建集中在一处(宏/工厂), 不许上层直接 new CDX12*

【问题4】CWorld 的所有权与线程安全 (正确性, 未变)
  - CWorld::ParseFile 里 new 的 CStaticMesh/CActor/CLevel 无处释放(析构为空)。
  - LoadAsync 里后台线程调 ParseFile/BuildActors, 与主线程 TickLoad/Tick 之间没有同步,
    BuildActors 写 PersistentLevel 时主线程可能正在 Tick 读它。
  - 新增: 渲染线程 _Flush 将读 World/FMeshBatch, 与游戏线程 Tick 并发, 同样无同步。
  建议: 最低限度在 LoadState 上加原子量/临界区; 析构补齐释放; 渲染数据考虑双缓冲。

【问题5】GetMeshBatch 硬编码 LOD0/Section0 (可接受, 记录在案)
  忽略 InViewProj 参数(视锥剔除/LOD 选择以后做), 只取第 0 个 LOD 和第 0 个 Section。
  多材质 Cube 出屏时再改。

【问题6】FMeshBatch 直接耦合 CStaticMesh (可接受, 记录在案)
  UE 的 FMeshBatch 只依赖 VertexFactory + 材质, 不认识具体 Mesh 类型。
  mini 阶段可以先这样, 做 SkeletalMesh 时再抽象。
